# 03. Бэкпортирование и протокольные трансляторы (Backporting)

## 1. Методология бэкпортирования: Аудит апстрима

При бэкпортировании мода или протокольного слоя (например, ViaFabricPlus или исправления сетевого стека) с новых версий на старые (например, с 26.x на 1.21.4):

> [!IMPORTANT]
> **НЕ ВСЕ ФИКСЫ АПСТРИМА ПРИМЕНИМЫ К СТАРОМУ КЛИЕНТУ:**
> - Апстрим часто реализует логику «эмулировать клиент 1.21 на клиенте 26.x».
> - При бэкпорте ваш клиент **уже является** старым клиентом!
> - Попытка портировать такие миксины создает мертвый код или крашит сборку, так как целевые классы и методы (например, `ShelfBlock`, `BlockTransformer`, `MinecraftClient.pauseGame`) физически **отсутствуют** в старой версии.
> - **Правило:** Всегда сверяйте целевой класс с байткодом целевой версии перед внедрением миксина.

## 2. Нативные бэкпорты и ранний перехват (На примере GLFW 3.4+ и RDP Fix)

В случаях, когда баг кроется в нативных библиотеках движка (например, баг центрирования курсора мыши в RDP при игре на старых версиях GLFW):

### 2.1. Ранняя инициализация через `IMixinConfigPlugin`:
Обычные инициализаторы Fabric (`PreLaunchEntrypoint`) или конструкторы NeoForge (`@Mod`) запускаются слишком поздно — графическое окно и нативный GLFW уже заблокированы загрузчиком FML.
- **Решение:** Использовать `IMixinConfigPlugin`:
  ```java
  public class EarlyNativeLoaderPlugin implements IMixinConfigPlugin {
      @Override
      public void onLoad(String mixinPackage) {
          // Вызывается за 5+ секунд до создания окна Minecraft!
          NativeUnpacker.loadPatchedLibraries();
          FmlConfigManager.disableEarlyWindow();
      }
      // ...
  }
  ```

### 2.2. Автоматическое управление `config/fml.toml` в NeoForge:
NeoForge по умолчанию включает раннее окно загрузки (`earlyWindowControl = true`), которое инициализирует ванильный GLFW до загрузки модов.
- Плагин миксина при старте автоматически проверяет `config/fml.toml` и перезаписывает `earlyWindowControl = false`, гарантируя запуск кастомных нативных библиотек.

### 2.3. Исправление диагонального дрифта курсора (Bit-Exact Quantization Fix):
При нормализации абсолютных координат `pos.x += (int)((data->mouse.lLastX / 65535.f) * width)` стандартное усечение (`cvttss2si` на x86) отсекает дробную часть вниз, теряя 1 пиксель в 99.6% случаев и создавая фантомный увод мыши влево-вверх `(-1, -1)`.
- Замена в бинарном коде инструкции усечения на округление к ближайшему целому (`cvtss2si` / `FCVTNS`) полностью устраняет дрифт.

## 3. Бэкпорт системы «Избранное» и верстка вкладок GUI

При портировании интерфейсных расширений в экраны выбора протокола старых версий (1.21 – 26.1.x):
1. **Звёздочка `★` в списке протоколов:**
   - Интерактивный тумблер с сохранением множества идентификаторов протоколов в конфигурационный файл (`SettingsSave`).
   - Отображение пустого состояния («Список избранного пуст») с подсказкой о нажатии на звёздочку.
2. **Геометрия заголовка экрана (Layout Offset Rule):**
   - Кнопка «Назад» (`<-`) в кастомных экранах обычно фиксируется по координатам `x = 5, y = 5` с шириной 20-30px.
   - Если вкладки переключения (`all` / `favorites`) центрируются по формуле `(width / 2) - 100`, на экранах с шириной меньше 250px левая вкладка накладывается на кнопку «Назад».
   - **Правило:** При размещении панелей вкладок всегда закладывать смещение вправо минимум на ширину одной кнопки (`+ 25px`): `x = (width / 2) - 100 + 25`.

## 4. Защита аутентификации от повреждённых подписей скинов (Authlib Fix)

При подключении через ViaFabricPlus к старым серверам, оффлайн-серверам или серверам за прокси-балансировщиками (BungeeCord / Velocity), свойства профиля игрока (`Property`) могут приходить с пустой строкой в качестве подписи:
- В ванильной библиотеке Mojang Authlib метод `Property.hasSignature()` проверяет только `this.signature != null`.
- Для строки `""` метод возвращает `true`, что приводит к вызову RSA-валидации и падению клиента с необработанным `SignatureException: Bad signature length: 0`.
- **Архитектурный фикс:**
  1. `@Overwrite` метода `Property.hasSignature()`:
     ```java
     return this.signature() != null && !this.signature().isEmpty();
     ```
  2. `@Inject(at = @At("HEAD"), cancellable = true)` в `validateProperty`:
     ```java
     if (property.signature() == null || property.signature().isEmpty()) {
         cir.setReturnValue(false);
     }
     ```
  3. В версиях до 26.3 целевой класс — `com.mojang.authlib.yggdrasil.YggdrasilServicesKeyInfo`.
  4. В версиях 26.3+ целевой класс — `com.mojang.authlib.services.MinecraftServicesKeyInfo`.
